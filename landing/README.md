# PriceRadar — статический лендинг для российского хостинга

Готов к загрузке на обычный виртуальный хостинг с Apache или Nginx. PHP, Node.js и базы данных не нужны.

## Состав

```
index.html              главная
privacy.html            политика конфиденциальности
terms.html              условия использования
404.html                страница ошибки
style.css               стили
icon.png                иконка и favicon
og.png                  картинка для соцсетей 1200×630
screen-home.png         скриншот главного экрана
screen-results.png      скриншот сравнения
screen-help.png         скриншот настроек
PriceRadar.apk          актуальная сборка (2.5)
robots.txt
.htaccess               настройки Apache
nginx.conf.example      пример для Nginx
sitemap.xml.example     карта сайта: заменить домен
README.md               этот файл
```

## 1. Домен и хостинг

1. Зарегистрируйте домен у российского регистратора (Reg.ru, Timeweb, Beget, RU-Center и т.п.).
2. Возьмите виртуальный хостинг с поддержкой **HTTPS** и **Apache/Nginx**.
3. Привяжите домен к хостингу, дождитесь делегирования NS.
4. Включите бесплатный SSL (Let's Encrypt) в панели хостинга.

## 2. Загрузка

Загрузите **содержимое папки `landing/`** в корень сайта:

- Apache/cPanel: `public_html/`
- ISPmanager: `www/<домен>/`
- Nginx: каталог из `root` в конфиге, например `/var/www/priceradar/`

Не загружайте `dist/`, `_agent/`, исходники Android и keystore — только файлы из `landing/`.

## 3. Настройка сервера

### Apache

Файл `.htaccess` уже в комплекте. Проверьте, что хостинг разрешает `AllowOverride All` / `.htaccess`. Он включает:

- HTTPS-редирект;
- правильный MIME для `.apk`;
- кодировку UTF-8;
- запрет листинга каталогов;
- 404 → `404.html`;
- сжатие и кэш.

Если хостинг не поддерживает `mod_headers`/`mod_expires`, закомментируйте соответствующие блоки — сайт продолжит работать.

### Nginx

Скопируйте `nginx.conf.example`, замените:

- `example.ru` на ваш домен;
- `/var/www/priceradar` на путь к сайту;
- пути к SSL-сертификату.

Затем `nginx -t && systemctl reload nginx`.

### MIME для APK

Проверьте:

```bash
curl -I https://<домен>/PriceRadar.apk
```

Должно быть:

```
HTTP/1.1 200 OK
Content-Type: application/vnd.android.package-archive
```

Если тип `application/octet-stream` — добавьте MIME в панели хостинга.

## 4. Проверка

- `https://<домен>/` — главная;
- `https://<домен>/privacy.html` — политика;
- `https://<домен>/terms.html` — условия;
- `https://<домен>/PriceRadar.apk` — скачивание APK;
- `https://<домен>/404.html` — ошибка;
- HTTP должен перенаправляться на HTTPS.

Проверьте на телефоне: скачивание APK, установка, переходы «Скачать» и «Политика».

## 5. Обновление APK

1. Соберите новую версию: `python tools/build.py`.
2. Скопируйте `dist/PriceRadar-<версия>.apk` в `landing/PriceRadar.apk`.
3. Обновите на странице:
   - версию (сейчас 2.5);
   - SHA-256 в блоке «Проверить файл». Получить:
     ```bash
     sha256sum PriceRadar.apk
     ```
4. Загрузите новый APK на хостинг.
5. Старые версии не удаляйте сразу — пользователи обновляются поверх, данные сохраняются.

## 6. Домен в мета-тегах

Сейчас все ссылки относительные, поэтому лендинг работает на любом домене. Когда домен выбран:

- при желании добавьте `canonical` и `og:url` с полным адресом;
- замените `example.ru` в `sitemap.xml.example` и переименуйте в `sitemap.xml`;
- добавьте `Sitemap: https://<домен>/sitemap.xml` в `robots.txt`.

## 7. Юридические данные

Перед публикацией добавьте в футер/условия данные владельца: ФИО/ИП/юрлицо, ИНН при необходимости, контактный e-mail. Сейчас там только ссылка на GitHub Issues.

Лендинг не является публичной офертой. Товарные знаки маркетплейсов принадлежат их владельцам.

## 8. Что не делать

- Не загружайте `keystore` и `keystore.properties`.
- Не выкладывайте исходники и внутренние заметки.
- Не включайте directory listing.
- Не используйте чужие скриншоты и логотипы маркетплейсов в качестве своего бренда.
